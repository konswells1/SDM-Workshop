Ensemble Model Fitting

Combining species distribution models and examining model disagreement

Why combine species distribution models?

In Fitting and Comparing Algorithms, we saw that a generalised linear model (GLM), a generalised additive model (GAM) and tree-based methods can describe different relationships between species records and environmental conditions. Their predictions may differ even when they use exactly the same occurrence data and predictors.

Ensemble modelling combines predictions from several fitted models. An ensemble may produce a more stable summary of the patterns suggested by different methods, but averaging models does not automatically make a prediction more accurate or ecologically correct. Models can share the same sampling bias, missing predictors and errors. Their predictions may also be strongly correlated.

This chapter explores both the average prediction and disagreement among models, using lesser horseshoe bat (Rhinolophus hipposideros) occurrence records and the same three environmental predictors as the earlier sections of the workshop.

TipLearning outcomes — optional research extension

This sections goes beyond the core practical excersises. You can complete the workshop’s GLM exercises without fitting an ensemble.

By the end of the examples, you should be able to:

  • Describe simple, weighted and threshold-based approaches to combining model predictions.
  • Produce an average ensemble from models fitted on the same training data.
  • Examine variation between individual model predictions and explain what it does—and does not—tell us about uncertainty.
  • Assess individual models and their ensemble using the same held-out test data.
  • Explain why ensemble weights must be chosen without using the final test observations.

The main example uses a GLM and a classification tree; a GAM and Random Forest are added when their packages are available. Additional biomod2 and sdm workflows are provided as research extensions and do not run automatically on the website.

2. Fit models to the same training observations

For our first ensemble, we combine predictions from different types of model. A GLM describes specified regression relationships, whereas a classification tree divides environmental space into groups according to predictor values. We can also add the GAM and Random Forest from the preceding chapter.

NotePackages for the optional algorithms

3. Combine the model predictions

3.1 Equal-weight average

A simple ensemble gives each included model the same influence. It is useful as a transparent starting point and does not require estimating extra performance weights.

3.2 Examine disagreement between models

The standard deviation of the model predictions measures how much the fitted algorithms disagree at each sampled location. It is not a confidence interval, and it does not include uncertainty about the occurrence records, background sampling, predictor data or future climate.

ensemble_test_sd <- apply(model_scores_test, 1, stats::sd)

3.3 Compare held-out discrimination

We calculate AUC for each individual model and for the equal-weight ensemble using the same reserved test records. We do not choose models or weights based on these results. AUC measures ranking of the two sampled classes; it is not evidence of absolute occupancy probability or transferability to other regions.

heldout_auc <- function(scores) {
  as.numeric(pROC::auc(pROC::roc(
    response = model_test$pa,
    predictor = as.numeric(scores),
    levels = c(0, 1), direction = "<", quiet = TRUE
  )))
}

auc_table <- data.frame(
  Model = c(colnames(model_scores_test), "Equal-weight ensemble"),
  Test_AUC = c(
    vapply(model_scores_test, heldout_auc, numeric(1)),
    heldout_auc(ensemble_test_mean)
  )
)
auc_table$Test_AUC <- round(auc_table$Test_AUC, 3)
knitr::kable(auc_table,
             caption = "Held-out presence–background AUC")

Explain: Did averaging improve AUC in this example? If not, does that make the ensemble pointless? Think about differences in ecological interpretation, model agreement and the purpose of the analysis. Do not repeatedly change the ensemble to optimise this test-set AUC: doing so would make the test results overly optimistic.

WarningWhy we do not weight models by the test AUC

The final test subset is reserved for assessment. If we use its AUC values to set ensemble weights, and then report the same test AUC as evidence of independent performance, the assessment has been used twice.

To use performance-weighted averaging, estimate weights using a separate validation subset or cross-validation within the training data. Then lock the modelling and weighting procedure before assessing the final test subset. A fully annotated example appears below as an optional exercise.

3.4 Optional research exercise: training-only performance weights

This example splits the training subset into an internal calibration part and a validation part. It fits temporary models on calibration data, obtains validation AUCs and uses only those values to define non-negative weights. The final fitted models from Section 2 still use the entire training set. The original held-out test data do not enter weight calculation.

The code is not run during website rendering. It is intended for investigating weighting choices in your own RStudio script, rather than for demonstrating that a weighted ensemble is always preferable.

set.seed(2027)
inside_presence <- which(model_train$pa == 1L)
inside_background <- which(model_train$pa == 0L)
calibration_rows <- sort(c(
  sample(inside_presence, floor(0.8 * length(inside_presence))),
  sample(inside_background, floor(0.8 * length(inside_background)))
))
calibration <- model_train[calibration_rows, , drop = FALSE]
validation <- model_train[-calibration_rows, , drop = FALSE]

cal_glm <- glm(
  pa ~ poly(elevation, 2) + poly(bio_1, 2) +
    poly(bio_12, 2),
  data = calibration, family = binomial()
)
cal_tree <- rpart::rpart(
  factor(pa, levels = c(0, 1)) ~ bio_1 + bio_12 + elevation,
  data = calibration, method = "class",
  control = rpart::rpart.control(cp = 0.01, minbucket = 8,
                                 xval = 0)
)

validation_scores <- data.frame(
  GLM = as.numeric(predict(cal_glm, validation,
                           type = "response")),
  Tree = as.numeric(predict(cal_tree, validation,
                            type = "prob")[, "1"])
)

if ("GAM" %in% names(model_scores_test)) {
  cal_gam <- mgcv::gam(
    pa ~ s(bio_1, k = 5) + s(bio_12, k = 5) +
      s(elevation, k = 5),
    data = calibration, family = binomial(), method = "REML"
  )
  validation_scores$GAM <- as.numeric(predict(
    cal_gam, validation, type = "response"))
}
if ("RF" %in% names(model_scores_test)) {
  set.seed(2027)
  cal_rf <- randomForest::randomForest(
    x = calibration[, predictors, drop = FALSE],
    y = factor(calibration$pa, levels = c(0, 1)),
    ntree = 250
  )
  validation_scores$RF <- as.numeric(predict(
    cal_rf, validation[, predictors, drop = FALSE],
    type = "prob")[, "1"])
}

# Only the internal validation labels are used for the weights.
validation_auc <- vapply(validation_scores, function(scores) {
  as.numeric(pROC::auc(pROC::roc(
    validation$pa, scores, levels = c(0, 1),
    direction = "<", quiet = TRUE
  )))
}, numeric(1))

# Use discriminatory ability above 0.5; avoid negative weights.
weight_strength <- pmax(validation_auc - 0.5, 0)
if (sum(weight_strength) == 0) {
  ensemble_weights <- rep(1 / length(weight_strength),
                          length(weight_strength))
} else {
  ensemble_weights <- weight_strength / sum(weight_strength)
}
names(ensemble_weights) <- names(validation_scores)
print(ensemble_weights)

# Apply the FIXED weights to predictions from models fitted to
# the entire training subset, on the held-out test samples.
stopifnot(setequal(names(ensemble_weights),
                   colnames(model_scores_test)))
ensemble_test_weighted <- as.numeric(
  as.matrix(model_scores_test[, names(ensemble_weights)]) %*%
    ensemble_weights
)
heldout_auc(ensemble_test_weighted)

Think about: How sensitive might these weights be to the particular internal split? For more robust research analyses, consider repeated cross-validation, spatially separated folds and background-sampling sensitivity. Models with highly correlated errors do not become independent merely because their weights differ.

4. Map the ensemble across the study area

The individual models must predict from exactly the same environmental raster cells. We then take the mean and standard deviation across the aligned predictions. The second map shows algorithm disagreement, not a complete uncertainty assessment.

predictor_rasters <- proj_stack[[predictors]]

glm_ensemble_map <- terra::predict(
  predictor_rasters, glm_multi,
  type = "response", na.rm = TRUE
)
names(glm_ensemble_map) <- "GLM"

tree_ensemble_map <- terra::predict(
  predictor_rasters, tree_model,
  fun = function(model, data, ...) {
    as.numeric(predict(model, newdata = data,
                       type = "prob")[, "1"])
  },
  na.rm = TRUE
)
names(tree_ensemble_map) <- "Tree"

ensemble_model_maps <- c(glm_ensemble_map, tree_ensemble_map)

if (!is.null(gam_model)) {
  gam_ensemble_map <- terra::predict(
    predictor_rasters, gam_model,
    type = "response", na.rm = TRUE
  )
  names(gam_ensemble_map) <- "GAM"
  ensemble_model_maps <- c(ensemble_model_maps, gam_ensemble_map)
}
if (!is.null(rf_model)) {
  rf_ensemble_map <- terra::predict(
    predictor_rasters, rf_model,
    fun = function(model, data, ...) {
      as.numeric(predict(model, newdata = data,
                         type = "prob")[, "1"])
    },
    na.rm = TRUE
  )
  names(rf_ensemble_map) <- "RF"
  ensemble_model_maps <- c(ensemble_model_maps, rf_ensemble_map)
}

ensemble_mean_map <- terra::app(ensemble_model_maps,

ensemble_sd_map <- terra::app(ensemble_model_maps,

names(ensemble_mean_map) <- "Ensemble_mean"
names(ensemble_sd_map) <- "Model_disagreement_SD"

old_par <- par(mfrow = c(1, 2))

par(old_par)

4.1 A note on threshold-based voting

A consensus map can also be produced by first classifying each model’s predicted score as above or below a threshold, and then calculating the proportion of models voting for the higher-score class. However, thresholds need justification and should be fixed without examining the final test set. Since the output scores of different algorithms are not necessarily calibrated to the same meaning, a single universal cutoff such as 0.5 is not automatically appropriate.

NoteResearch extension: calculate consensus using training-derived thresholds

Choose a threshold for each model using training-only cross-validation, classify that model’s spatial predictions using its chosen threshold, and average the resulting 0/1 rasters. The map then represents the proportion of models voting for a high-score class, not the probability of species occurrence. Avoid labelling the two classes as confirmed presence and absence.

4.2 Optional: transfer the ensemble to future climate

The verified data/Clim_cmip6_2041_2060_UK.tif supplies the BCC-CSM2-MR projection for SSP1-2.6, 2041–2060. An ensemble can be projected to this scenario only if the predictors have the same definitions, units and compatible spatial grids as the training rasters. Elevation is held constant in this example. Future climate projections may contain conditions outside the calibration range, making extrapolated model scores especially uncertain.

future_climate <- terra::rast(
  "data/Clim_cmip6_2041_2060_UK.tif"
)
stopifnot(
  all(c("bio_1", "bio_12") %in% names(future_climate)),
  terra::compareGeom(future_climate[["bio_1"]],
                     predictor_rasters[["bio_1"]])
)

future_predictors <- c(
  future_climate[[c("bio_1", "bio_12")]],
  predictor_rasters[["elevation"]]
)
stopifnot(identical(names(future_predictors), predictors))

future_glm <- terra::predict(
  future_predictors, glm_multi, type = "response", na.rm = TRUE
)
future_tree <- terra::predict(
  future_predictors, tree_model,
  fun = function(model, data, ...) {
    as.numeric(predict(model, data, type = "prob")[, "1"])
  }, na.rm = TRUE
)
future_maps <- c(future_glm, future_tree)

if (!is.null(gam_model)) {
  future_maps <- c(future_maps, terra::predict(
    future_predictors, gam_model,
    type = "response", na.rm = TRUE

}
if (!is.null(rf_model)) {
  future_maps <- c(future_maps, terra::predict(

future_ensemble_mean <- terra::app(future_maps, fun = mean)
ensemble_score_difference <- future_ensemble_mean - ensemble_mean_map

plot(ensemble_score_difference,

This difference map shows a change in fitted model scores under one climate scenario, not a forecast of where bats will definitely occur or disappear. Agreement across algorithms does not measure agreement across GCMs, SSPs, background samples or dispersal assumptions.

5. Other R tools for ensemble species distribution modelling

Manually combining predictions is valuable for learning, but research projects often need multiple background samples, repeated or spatial cross-validation, hyperparameter tuning and more detailed output management. The specialised packages below support such workflows. These examples start a new analysis, rather than using the Chapter 6 held-out test set directly; their evaluation scores should not be placed alongside the manual ensemble AUC without a common independent assessment.

5.1 biomod2: multi-algorithm ensembles

biomod2 can fit several SDM algorithms, manage pseudo-absence replicates, perform cross-validation and construct ensemble predictions. Its current interface uses SpatRaster environmental inputs and uses AUCroc to name the ROC/AUC metric. It also creates modelling files in the working directory, so a dedicated research project or subdirectory is recommended.

The example below uses presence locations and asks biomod2 to sample its own pseudo-absences. This is not the same background design or training/test partition used in the manual ensemble above, and the resulting scores are not directly comparable. The code requires the presence_sf object prepared in Chapter 5 and is not executed during website rendering.

library(biomod2)
library(sf)
library(terra)

if (!exists("presence_sf")) {
  stop("Recreate presence_sf from the Chapter 5 occurrence workflow.")
}
presence_on_grid <- sf::st_transform(
  presence_sf, terra::crs(predictor_rasters)
)
xy <- sf::st_coordinates(presence_on_grid)[, 1:2, drop = FALSE]

biomod_data <- biomod2::BIOMOD_FormatingData(
  resp.var = rep(1L, nrow(xy)),
  resp.xy = xy,
  expl.var = predictor_rasters,
  resp.name = "Rhinolophus_hipposideros",
  PA.nb.rep = 2,
  PA.nb.absences = nrow(xy),
  PA.strategy = "random"
)

biomod_models <- biomod2::BIOMOD_Modeling(
  bm.format = biomod_data,
  modeling.id = "EnsembleResearch",
  models = c("GLM", "GAM", "RF"),
  CV.strategy = "random",
  CV.nb.rep = 2,
  CV.perc = 0.7,
  OPT.strategy = "bigboss",
  metric.eval = "AUCroc",
  seed.val = 2026
)

# Use internal validation, not an external final test set, for weights.
biomod_ensemble <- biomod2::BIOMOD_EnsembleModeling(
  bm.mod = biomod_models,
  em.by = "PA+run",
  em.algo = c("EMmean", "EMcv", "EMwmean"),
  metric.select = "AUCroc",
  metric.select.dataset = "validation"
)

biomod_current <- biomod2::BIOMOD_Projection(
  bm.mod = biomod_models,
  new.env = predictor_rasters,
  proj.name = "current"
)

biomod_forecast <- biomod2::BIOMOD_EnsembleForecasting(
  bm.em = biomod_ensemble,
  bm.proj = biomod_current
)

# Inspect what biomod2 actually generated before selecting map layers.
print(biomod2::get_predictions(biomod_forecast))
WarningChoosing a pseudo-absence strategy in biomod2

biomod2 treats a supplied 0 in a binary response as an absence label. Opportunistically sampled background locations should not be passed to the package and described as confirmed survey absences. The example above supplies presences and generates pseudo-absence samples through the package, with their interpretation clearly stated.

For research, justify the accessible area, compare plausible pseudo-absence strategies and carry out appropriately spatial validation. Do not assume that a larger number of algorithms or pseudo-absence samples necessarily improves ecological inference.

5.2 sdm: an alternative modelling framework

The sdm package provides functions for defining environmental modelling data, fitting several algorithms and obtaining their evaluation results. It can accept training and independent test tables, but its model objects and evaluation conventions differ from those used in biomod2. Check which algorithms and package dependencies are available before fitting a large set of models.

library(sdm)

sdm_input <- sdm::sdmData(
  pa ~ bio_1 + bio_12 + elevation,
  train = model_train,
  test = model_test
)

# This fits new models; it does not reuse the Chapter 8 fitted objects.
sdm_models <- sdm::sdm(
  formula = pa ~ bio_1 + bio_12 + elevation,
  data = sdm_input,
  methods = c("glm", "gam", "rf")
)

# Distinguish training and independent-test evaluation in the results.
print(sdm::getEvaluation(sdm_models))

Research connection: A package can automate model fitting and evaluation, but it cannot decide whether the sampled background represents a defensible ecological comparison. Software also cannot make a randomly held-out observation spatially independent of nearby training observations.

6. Practise, interpret and extend

NoteExercises — ensemble modelling
  1. Read and inspect: Compare the GLM, tree, GAM and Random Forest scores at the same held-out sites. Which models agree most closely, and are their output scales equivalent in meaning?
  2. Change: Refit the classification tree with a different cp value using training data only. Inspect how the ensemble mean and disagreement map change. This is a sensitivity exercise; do not use the held-out AUC repeatedly to tune cp.
  3. Explain: Why might models agree on a misleading spatial pattern when all have been trained on the same biased occurrences and background locations?
  4. Research extension: Calculate performance weights using the internal training-only example and compare their values with equal weighting. How do the fitted model structures, background design and spatial validation affect your conclusions?

Describe your modelling decisions and interpretations in your own annotated .R script. For independent research applications, report model settings, sampling design, spatial validation, algorithm agreement and all major sources of uncertainty.

Software, data provenance and optional reproducible downloads

Preparing data for species distribution modelling

This is an optional reference chapter. You can complete the core SDM practical using the prepared datasets supplied in the student materials. You do not need to download data from GBIF or WorldClim before fitting your first model.

The examples below show how the workshop inputs can be obtained and documented in R. They are intended for students who want to repeat the preparation workflow, test alternative data sources or develop their own research project. The download code is displayed but not executed when this page is built. If you try the examples, run them in RStudio from your own workshop project folder.

TipThree ways to obtain data for your own SDM
  • Collect your own observations: use field surveys, monitoring or systematic sampling; distinguish observed presences, credible absences and non-detections.
  • Reuse existing occurrence records: obtain suitably documented data from research collections, museums or biodiversity databases such as GBIF.
  • Use environmental information: obtain climate, elevation, land-cover or other predictors from existing datasets or measurements, at spatial and temporal resolutions appropriate to your question.

In every case, document where the data came from, what they represent, their limitations and any processing decisions. A downloaded presence record is not automatically a verified absence at any other location.

Why supply prepared data? Online services can be slow or temporarily unavailable, and two live queries may return different records. A fixed, documented snapshot makes the exercises in this workshop easier to reproduce and compare. Using prepared inputs does not remove the need to clean data, select predictors, fit models, evaluate them or interpret their outputs.

3. Reconstruct the map boundaries (optional)

Natural Earth provides world and national administrative boundaries. The original workshop uses the objects World_sf, UK_sf, UK_admin_sf and WalesEast_admin_sf in some examples.

World_sf <- rnaturalearth::ne_countries(
  scale = "medium", returnclass = "sf"
)
UK_sf <- rnaturalearth::ne_countries(
  scale = "medium", country = "United Kingdom", returnclass = "sf"
)

# Administrative boundaries are an OPTIONAL extension.
# Depending on package versions, ne_states() can require
# additional Natural Earth data / rnaturalearthhires.
UK_admin_sf <- rnaturalearth::ne_states(
  country = "United Kingdom", returnclass = "sf"
)

# Check the actual attribute names and values before subsetting.
names(UK_admin_sf)
unique(UK_admin_sf$region)
WalesEast_admin_sf <- UK_admin_sf[
  !is.na(UK_admin_sf$region) & UK_admin_sf$region == "East Wales", ]

if (nrow(WalesEast_admin_sf) == 0) {
  warning("East Wales was not identified; inspect the administrative data.")
}

Boundary definitions can vary with the data source and scale. For research, verify that your study extent is ecologically justified and recorded with its spatial reference system.

4. Download environmental predictors (optional)

The example uses WorldClim 2.1 historical bioclimatic variables, which represent a 1970–2000 climatological baseline, rather than today’s weather. The workshop uses 5-arc-minute climate grids and an elevation dataset at finer resolution. Different raster resolutions must be reconciled before predictors are combined in one model.

The optional code below creates a separate data/rebuilt/ directory. It does not overwrite the verified files supplied for the practical. Run the boundary code above first to create UK_sf.

dir.create("data/downloads", recursive = TRUE, showWarnings = FALSE)
dir.create("data/rebuilt", recursive = TRUE, showWarnings = FALSE)

# Historical WorldClim 2.1 bioclimatic variables (19 layers)
Clim_global <- geodata::worldclim_global(
  var = "bio", res = 5, path = "data/downloads"
)

# Crop and mask to the UK study boundary
uk_vector <- terra::vect(UK_sf)
Clim_UK_rebuilt <- terra::mask(
  terra::crop(Clim_global, uk_vector), uk_vector
)

# Check original naming and match BIO1...BIO19 to their source order
names(Clim_global)
stopifnot(terra::nlyr(Clim_UK_rebuilt) == 19)
names(Clim_UK_rebuilt) <- paste0("bio_", 1:19)

terra::writeRaster(
  Clim_UK_rebuilt, "data/rebuilt/Clim_UK.tif", overwrite = TRUE
)

# Elevation: a different spatial resolution from the climate predictors
Elev_raw <- geodata::elevation_30s(
  country = "GB", path = "data/downloads"
)
Elev_UK_rebuilt <- terra::mask(
  terra::crop(Elev_raw, uk_vector), uk_vector
)
terra::writeRaster(
  Elev_UK_rebuilt, "data/rebuilt/Elev_UK.tif", overwrite = TRUE
)
TipWhy raster alignment matters

Before combining layers, inspect their coordinate reference systems, resolution, extent and cell alignment. Continuous elevation can be resampled to a coarser climate grid, but the choice of resolution changes the information retained.

# Run after rebuilding the historical climate and elevation layers
if (!terra::same.crs(Elev_UK_rebuilt, Clim_UK_rebuilt)) {
  Elev_aligned <- terra::project(
    Elev_UK_rebuilt, Clim_UK_rebuilt[[1]], method = "bilinear"
  )
} else {
  Elev_aligned <- terra::resample(
    Elev_UK_rebuilt, Clim_UK_rebuilt[[1]], method = "bilinear"
  )
}
names(Elev_aligned) <- "elevation"

Env_UK_stack <- c(Clim_UK_rebuilt, Elev_aligned)
names(Env_UK_stack)
terra::compareGeom(Clim_UK_rebuilt[[1]], Elev_aligned)

Resampling does not create new fine-scale environmental information. For categorical land-cover predictors, use a suitable categorical resampling method instead of bilinear interpolation.

Future climate scenarios — research extension

CMIP6 climate projections are conditional on the chosen global climate model (GCM), Shared Socioeconomic Pathway (SSP) and time period. The example below uses BCC-CSM2-MR, SSP1-2.6 (ssp = "126"), 2041–2060, at 5 arc-minutes. It does not represent SSP5-8.5; that would require ssp = "585" and explicit relabelling of the results.

# Run after the boundary and historical-climate examples
Clim_future_global <- geodata::cmip6_world(
  var = "bioc",
  ssp = "126",                    # SSP1-2.6, NOT SSP5-8.5
  model = "BCC-CSM2-MR",
  time = "2041-2060",
  res = 5,
  path = "data/downloads"
)

Clim_future_UK <- terra::mask(
  terra::crop(Clim_future_global, uk_vector), uk_vector
)

names(Clim_future_global)          # inspect source layer order
stopifnot(terra::nlyr(Clim_future_UK) == 19)
names(Clim_future_UK) <- paste0("bio_", 1:19)

# Compare matching layers and raster grids BEFORE saving
stopifnot(terra::compareGeom(
  Clim_UK_rebuilt, Clim_future_UK, stopOnError = FALSE
))
mean_difference <- terra::global(
  abs(Clim_future_UK[[1]] - Clim_UK_rebuilt[[1]]),
  fun = "mean", na.rm = TRUE
)[1, 1]
stopifnot(is.finite(mean_difference), mean_difference > 0)

terra::writeRaster(
  Clim_future_UK,
  "data/rebuilt/Clim_cmip6_2041_2060_UK.tif",
  overwrite = TRUE
)

When assessing future projections, distinguish climate change from predictor extrapolation, check predictor comparability and consider multiple GCMs and pathways rather than interpreting one map as a definitive forecast.

5. Retrieve species observations from GBIF (optional)

The teaching example uses the lesser horseshoe bat, Rhinolophus hipposideros, in the United Kingdom (country = "GB" in GBIF). GBIF aggregates records from multiple publishers; downloaded coordinates can include duplicates, imprecise localities and sampling biases. Records must be inspected and cleaned before modelling.

The code below illustrates a limited GBIF search. It is appropriate for learning how an API query works, not as a complete or publication-ready occurrence dataset. Search results may change over time and limiting the number returned does not provide a representative sample.

species_name <- "Rhinolophus hipposideros"
match_species <- rgbif::name_backbone(name = species_name)
species_key <- match_species$speciesKey
stopifnot(length(species_key) == 1, !is.na(species_key))

occ_result <- rgbif::occ_search(
  taxonKey = species_key,
  country = "GB",
  hasCoordinate = TRUE,
  limit = 2000
)
occ_df_rhinhipp <- occ_result$data

# Explore the records and document what was actually retrieved
nrow(occ_df_rhinhipp)
names(occ_df_rhinhipp)
head(occ_df_rhinhipp[, intersect(
  c("species", "decimalLongitude", "decimalLatitude", "eventDate"),
  names(occ_df_rhinhipp)
)])
retrieval_date <- Sys.Date()
retrieval_date

Target-group records for background-sampling demonstrations

The original workshop also retrieves other bat observations to illustrate target-group background sampling. These data are records of other bat species, not confirmed absences of the focal species. They must be filtered and assessed before use in a model.

bat_match <- rgbif::name_backbone(name = "Chiroptera")
bat_key <- bat_match$usageKey
stopifnot(length(bat_key) == 1, !is.na(bat_key))

bat_result <- rgbif::occ_search(
  taxonKey = bat_key,
  country = "GB",
  hasCoordinate = TRUE,
  limit = 10000
)
bat_df <- bat_result$data

# Retain records with coordinates and a taxon name
required_columns <- c("species", "decimalLongitude", "decimalLatitude")
stopifnot(all(required_columns %in% names(bat_df)))
target_group_df <- dplyr::filter(
  bat_df,
  !is.na(.data$species),
  .data$species != species_name,
  !is.na(.data$decimalLongitude),
  !is.na(.data$decimalLatitude)
)
target_group_df <- dplyr::select(
  target_group_df,
  dplyr::all_of(required_columns)
)
target_group_sf <- sf::st_as_sf(
  target_group_df,
  coords = c("decimalLongitude", "decimalLatitude"),
  crs = 4326
)
NoteGBIF citation and reproducible research

A GBIF occ_search() query does not automatically create a single DOI-assigned occurrence download. For research and publication, consider the GBIF download system and preserve the resulting DOI and download information. Keep the exact taxon and spatial filters, retrieval date, record-selection rules, quality-control steps, licences and attribution to original publishers.

A time-stamped saved snapshot is often more reproducible than repeatedly asking for the latest available records; the appropriate observation period depends on the ecological question. For detailed guidance, consult GBIF citation guidelines.

6. Save a reproducible data snapshot (optional)

The code below illustrates the same object names used in the original workshop, so the subsequent SDM chapters can locate prepared boundaries and species records. Run the relevant optional examples above first. Saving to data/rebuilt/ protects the distributed student files.

needed_objects <- c(
  "World_sf", "UK_sf", "UK_admin_sf", "WalesEast_admin_sf",
  "species_name", "occ_df_rhinhipp", "target_group_sf"
)
missing_objects <- needed_objects[
  !vapply(needed_objects, function(x) {
    exists(x, envir = .GlobalEnv, inherits = FALSE)
  }, logical(1))
]
if (length(missing_objects)) {
  stop("First create these objects: ", paste(missing_objects, collapse = ", "))
}

dir.create("data/rebuilt", recursive = TRUE, showWarnings = FALSE)
save(
  World_sf, UK_sf, UK_admin_sf, WalesEast_admin_sf,
  species_name, occ_df_rhinhipp, target_group_sf,
  file = "data/rebuilt/workshop_data.RData"
)

# Inspect the saved object names in a separate environment
check_snapshot <- new.env(parent = emptyenv())
load("data/rebuilt/workshop_data.RData", envir = check_snapshot)
ls(check_snapshot)

For independent research, it is often clearer to save individual .rds or .csv tables plus raster files, with a short data dictionary and provenance file, rather than relying entirely on a single .RData workspace. Never overwrite the original field records or downloaded snapshot without preserving the source and processing history.

7. What to record for reproducible SDM research

Before presenting results in a dissertation or publication, document the following decisions:

  1. Ecological question and study extent: species, time period, spatial boundary and the area accessible to the species.
  2. Occurrence provenance: surveys or database sources, retrieval date, persistent citations, filters and coordinate uncertainty.
  3. Environmental predictors: source, baseline, resolution, units, projections, and the ecological justification for selection.
  4. Sampling and quality control: duplicated observations, sampling bias, presence/absence/background definitions, and missing-data handling.
  5. Modelling and validation: training/test separation, spatial dependence, tuning, evaluation measures and uncertainty.
  6. Reproducible outputs: input snapshots, processing scripts, package versions and enough metadata to reconstruct results.

The ODMAP reporting framework is a useful reference for organising these decisions. Detailed modelling choices are introduced throughout the workshop’s practical and advanced chapters.
